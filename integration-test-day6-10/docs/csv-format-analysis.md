# 支付宝 / 微信账单格式分析（已用真实账单校准）

> 本文档基于用户提供的真实导出文件（2026-10-23 至 2026-11-23）核对完成，替换了此前的工作假设。
> 解析结果与文件头部统计完全一致：支付宝支出 25 / 不计收支 7；微信支出 45 / 收入 6 / 中性 3。

## 0. 关键结论与两个待确认项

1. **微信实际导出为 xlsx，不是 CSV**（文件为 Excel 2007+ 格式）。SRS F-P0-01 表述为“导入微信 CSV”，与实际不符。解析器已通过表格适配层同时支持 CSV 与 xlsx；建议同步更新 SRS 措辞，或在导入说明中明确“微信 xlsx 由系统直接解析”。
2. 真实账单存在 **0.00 元记录**（信用借还、解冻等），解析器将其单列至 `zero_amount`，默认不参与金额统计；是否保留这些流水需团队确认。
3. “不计收支/中性”当前统一映射为 `Direction.TRANSFER` 以保证不计入支出；是否新增 `NON_CASH` 枚举需团队确认。

## 1. 共性

| 项 | 结论 |
| --- | --- |
| 编码 | 支付宝 CSV 为 GBK，按超集 GB18030 解码；兼容 UTF-8/BOM |
| 金额 | 文件内为“元”，精确转换为整数分，全程不使用 float |
| xlsx 数值金额 | openpyxl 读出为 float，经 `Decimal(str(value))` 还原为干净字符串后再转分 |
| xlsx 时间 | openpyxl 读出为 datetime，统一格式化为 `YYYY-MM-DD HH:MM:SS` |
| 单号 | 长数字，按文本保留，禁止数值化（防止科学计数法丢精度） |

## 2. 支付宝（CSV，表头第 24 行，13 列）

真实表头：
`交易时间, 交易分类, 交易对方, 对方账号, 商品说明, 收/支, 金额, 收/付款方式, 交易状态, 交易订单号, 商家订单号, 备注,（末尾空列）`

| 逻辑字段 | 真实列名 | 说明 |
| --- | --- | --- |
| transacted_at | 交易时间 | `YYYY-MM-DD HH:MM:SS` |
| type | 交易分类 | 支付宝自带分类：餐饮美食/交通出行/日用百货/信用借还/退款/账户存取等，非本系统 Category |
| counterparty | 交易对方 | 已脱敏（如 3***涛） |
| item_name | 商品说明 | 分类关键词匹配输入 |
| direction | 收/支 | **支出 / 收入 / 不计收支** |
| amount | 金额 | 如 `15.00`、`0.00`、`0.01` |
| status | 交易状态 | 交易成功/交易关闭/退款成功等 |
| external_id | 交易订单号 | 长数字文本，数据行带尾随 Tab，已清洗 |

- 不计收支包含：信用借还、账户存取（充值）、还款、退款等。
- 退款在支付宝标记为“不计收支”，金额为正（如押金退款 `0.01`），并非负数。

## 3. 微信（xlsx，表头第 18 行，11 列）

真实表头：
`交易时间, 交易类型, 交易对方, 商品, 收/支, 金额(元), 支付方式, 当前状态, 交易单号, 商户单号, 备注`

| 逻辑字段 | 真实列名 | 说明 |
| --- | --- | --- |
| transacted_at | 交易时间 | datetime |
| type | 交易类型 | 商户消费/转账/微信红包/群收款/零钱提现/零钱充值/益禾堂-退款等 |
| counterparty | 交易对方 | |
| item_name | 商品 | |
| direction | 收/支 | **支出 / 收入 / "/"（中性）** |
| amount | 金额(元) | 数据区**不带 ¥**，为数值；¥ 仅出现在备注（如服务费） |
| status | 当前状态 | 支付成功/已存入零钱/已全额退款/提现已到账等 |
| external_id | 交易单号 | 文本 |
| note | 备注 | 多为 "/" |

- 中性交易（收/支="/"）：零钱充值、零钱提现，共 3 笔。
- 真实退款对：原消费（支出，状态“已全额退款”）与退款（收入，交易类型“益禾堂-退款”）金额相同、时间相邻，是第 8 天退款配对的真实样本。

## 4. 坏账单处理规则（对应 SRS 5.3）

| 类型 | 行为 |
| --- | --- |
| 空行 / 纯空白行 | 跳过，不计入数据行 |
| 缺关键列（单号/金额/收支/时间） | 该行拒识并记录原因，其余行继续，不崩溃 |
| 非法金额（空、非数字、>2 位小数） | 该行拒识 |
| 0.00 元 | 进入 `zero_amount`，不参与金额统计 |
| 乱码 / 无效字节（仅 CSV） | 解码 replace 兜底，标记 `had_decoding_errors`，继续解析有效行 |
| 找不到表头 | 抛致命 `ParseError`，不产生脏数据 |
